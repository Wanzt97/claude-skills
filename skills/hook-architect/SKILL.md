# Architecte de hooks

Méthode tirée de la vidéo de **Kael Cruz** sur l'art du hook. Ne pas utiliser pour rédiger la vidéo ou la page entière (funelio-copy:copywriter), ni pour le texte de miniature (vidiq-thumbnail-text).

Un hook n'est **pas une introduction, c'est une interruption**. Le spectateur a le pouce prêt à partir ; le hook doit créer un **micro-choc cognitif** (« attends, quoi ? ») en fracturant une certitude : la tension entre ce qu'il croit savoir et ce qu'il réalise ne pas savoir.

Wanzt apprend la méthode en l'utilisant : **chaque hook livré affiche en dessous la structure qui l'a produit**, cases remplies.

# Étape 0 — Choisir le mode

| Situation | Mode |

| Il lance le skill sans contexte (/hook-architect, « lance le questionnaire hook ») | Demander le mode |

Pour demander le mode : AskUserQuestion « Comment veux-tu construire ton hook ? » — options : Questionnaire complet (8 questions, 5 hooks) — Un framework précis (3 variantes) — Réponse rapide (ton sujet, 3 hooks tout de suite) — Réparer un hook.

Si « Un framework précis » : seconde AskUserQuestion avec 1. Croyance retournée — 2. Coût caché — 3. Erreur intelligente — 4. Phrase impossible à ignorer. (La démonstration dépend d'une preuve : elle passe par le questionnaire complet.)

Ne jamais reposer une question dont Wanzt a déjà donné la réponse.

# La méthode

## Loi fondamentale : clair sur le sujet, incomplet sur la réponse

Trop flou → il ne comprend pas, il part. Trop complet → il a la réponse, il part. Test : après le hook, il peut dire *de quoi ça parle* mais pas *quelle est la réponse*. Un bon hook retient les bonnes personnes ; qu'un non-concerné parte est un succès.

## La chaîne psychologique (toujours avant d'écrire)

1. **Sujet** — de quoi parle réellement le contenu.
2. **Douleur** — la frustration que le spectateur vit déjà, dans ses mots.
3. **Croyance classique** — ce qu'il pense être la cause.
4. **Vérité plus profonde** — la vraie cause : différente mais crédible.
5. **Assembler avec CLAC**, puis compresser.

Sans croyance à retourner, pas de tension.

## CLAC

- **C — Contexte** : de quoi ça parle, en 3 secondes. ❌ « Il y a quelque chose que j'ai compris récemment… » ✅ « Si tes vidéos ne retiennent personne, le problème vient de tes 10 premières secondes. »
- **L — Lean-in** : la raison personnelle de rester. Leviers : bénéfice, douleur, croyance partagée, image mentale (« Ton spectateur passe devant ta vitrine à 70 km/h »).
- **A — Arrêt** : la rupture — *mais*, *pourtant*, *sauf que*, *le vrai problème*.
- **C — Contre-direction** : l'angle inattendu mais crédible, qui installe la question à laquelle le contenu répondra.

## Les 5 frameworks

Une phrase s'utilise une fois, une structure toute une vie.

### 1 — La croyance retournée
`Tu crois que [croyance classique], mais en réalité [vérité plus profonde].`
- **Effet** : fissure une idée tenue pour vraie ; le cerveau reste pour vérifier. Idéal éducatif et analyse.
- **Cases** : `[croyance classique]` = idée que l'audience défend vraiment, dite avec ses mots. `[vérité plus profonde]` = nommée, jamais expliquée.
- **Variantes** : `On t'a dit que [X]. C'est faux : [Y].` — `Tu crois que [X], mais les meilleurs [rôle] [ce qu'ils font vraiment].` — `[X] ? C'est ce que je croyais aussi. Jusqu'à ce que je comprenne [Y].` (l'aveu désamorce une audience qui n'aime pas qu'on la corrige)
- **Kael Cruz (07:14)** : « Tu crois que vendre, c'est convaincre, mais les meilleurs vendeurs ne convainquent pas — ils révèlent un problème que le client ressentait déjà. » → [croyance] = vendre, c'est convaincre ; [vérité] = révéler un problème déjà ressenti. « Les meilleurs vendeurs » remplace « en réalité » : la vérité devient plus crédible.
- **Piège** : donner toute la vérité d'un coup.
- **Questions** : idée reçue de l'audience *(ce qu'on va casser)* → réalité que le contenu va démontrer *(la contre-direction, à prouver)*.

### 2 — Le coût caché
`Le vrai coût de [mauvaise action], ce n'est pas [conséquence évidente]. C'est [conséquence cachée].`
- **Effet** : un problème visible (rassurant) devient un danger invisible (inquiétant). Très fort en business, pubs, VSL.
- **Cases** : `[mauvaise action]` = comportement concret que l'audience a déjà. `[conséquence évidente]` = ce qu'elle accepte. `[conséquence cachée]` = plus grande, cumulative, invisible, défendable.
- **Variantes** : `Le vrai piège de [action], ce n'est pas juste [évident], c'est [caché].` — `Tu penses que [action] te fait perdre [évident]. En réalité, ça te fait perdre [caché].`
- **Kael Cruz (07:39)** : « Le vrai piège d'un mauvais hook, ce n'est pas juste de perdre des vues, c'est d'entraîner l'algorithme à croire que personne ne te veut. » → [action] = mauvais hook ; [évident] = perdre des vues (« juste » le minimise) ; [caché] = l'algorithme qui apprend que personne ne te veut.
- **Piège** : la peur gratuite, exagérée jusqu'à perdre la crédibilité.
- **Questions** : mauvaise habitude de l'audience *(elle doit se reconnaitre)* → ce qu'elle pense que ça coûte *(le coût accepté)* → ce que ça coûte vraiment *(le danger invisible)*.

### 3 — L'erreur intelligente
`Les [audience] intelligents font souvent cette erreur : [erreur]. Et c'est exactement pour ça que [conséquence].`
- **Effet** : valorise avant de montrer la faille ; le spectateur se sent concerné, pas attaqué. Pour une audience ambitieuse.
- **Cases** : `[audience]` = groupe précis + qualificatif valorisant (remplacer « créateurs » par l'audience réelle). `[erreur]` = erreur de gens compétents, souvent par excès d'une qualité. `[conséquence]` = symptôme observable déjà constaté.
- **Variantes** : `Plus tu es [qualité], plus tu risques de [erreur].` — `Si tu es [audience] et que [conséquence], ce n'est pas un manque de talent. C'est cette erreur : [erreur].`
- **Kael Cruz (08:03)** : « Les créateurs intelligents font souvent cette erreur : ils donnent la réponse trop vite, et c'est exactement pour ça que leur contenu s'effondre après 20 secondes. » → [audience] = créateurs intelligents ; [erreur] = vouloir être utile trop tôt ; [conséquence] = la chute visible dans les stats.
- **Piège** : une erreur bête — le compliment sonne faux.
- **Questions** : audience et qualité qu'elle veut qu'on lui reconnaisse → erreur même des meilleurs → résultat frustrant qu'elle cause.

### 4 — La phrase impossible à ignorer
`[Déclaration forte]. Et une fois que tu as compris ça, [conséquence].` (seconde partie optionnelle)
- **Effet** : affirmation nette, presque brutale ; arrête le scroll par l'assurance. Ouverture de Short et **re-hook** au milieu d'une vidéo longue.
- **Cases** : `[déclaration forte]` = 12 mots max par phrase, au présent, sans « je pense », **contestable**. `[conséquence]` = ce qui change pour le spectateur.
- **Variantes** : `[X] n'est pas fait pour [ce qu'on croit], il est fait pour [autre chose].` — `[Déclaration]. Le reste est du bruit.`
- **Kael Cruz (08:31)** : « Un hook n'est pas fait pour introduire une vidéo, il est fait pour empêcher quelqu'un de partir. » → déclaration seule, sans conséquence : le spectateur la tire lui-même.
- **Piège** : la banalité déguisée. Test : quelqu'un pourrait-il répondre « c'est faux » ?
- **Questions** : phrase la plus tranchée sur le sujet → ce qui change pour le spectateur (facultatif).

### 5 — La démonstration
`[« Je vais te montrer pourquoi… »] → [preuve ou exemple raté à l'écran] → [disséqué en direct, sans tout révéler]`
- **Effet** : prouver au lieu d'annoncer ; les démonstrations retiennent mieux que les explications.
- **Kael Cruz (08:59)** : « Je vais te montrer pourquoi cette phrase est un mauvais hook. » *(affiche « Bienvenue dans cette vidéo, aujourd'hui on parle de storytelling »)* puis il la dissèque : ni tension, ni promesse, ni raison de rester.
- **Piège** : une démo qui montre seulement qu'une chose existe retient moins qu'une démo en action.

## Hook visuel, rétention, émotion

- **Texte à l'écran** : 3 à 6 mots, condense sans répéter la voix. **Mouvement** : attire l'œil sans voler l'idée. **Composition** : l'image raconte l'univers avant la première phrase.
- **Après le hook** : vitesse vers la valeur (une preuve = une minute de plus), re-hooks à chaque transition, phrases courtes au début.
- **Émotion** : chaque hook promet une émotion (curiosité, peur de rater, soulagement, enfin compris) et la nomme.

# Les modes

## Règles des modes A et B

- Une question à la fois, progression affichée (`Question 3/8`), une ligne « pourquoi » sous chaque question.
- Choix → AskUserQuestion (2 à 4 options). Ouvertes → en texte.
- « Je ne sais pas » ou réponse vague → proposer 3 réponses tirées de ce qu'il a dit. Ne jamais bloquer.
- Réponse faible → le dire en une phrase et proposer mieux ; il tranche.
- Réponses incohérentes entre elles (sujet et audience qui ne collent plus) → s'arrêter, nommer l'incohérence, proposer 2 façons de recoller.
- Fait contestable → le signaler.

## Mode A — Questionnaire complet

1. **Format** — Short/Reel/TikTok, vidéo YouTube longue, post LinkedIn, email/VSL/pub.
2. **Sujet** en une phrase. Un thème (« l'IA en Afrique ») n'est pas un sujet → proposer 3 angles.
3. **Audience** : une personne, pas une catégorie → sinon 3 portraits précis.
4. **Douleur** dans ses mots. Un constat général n'est pas une douleur ; s'il ressemble à une croyance, le garder pour 5.
5. **Croyance classique**.
6. **Vérité plus profonde** — contredit vraiment 5, et le contenu peut la prouver.
7. **Preuve** — démo à l'écran, chiffre/fait/cas client, exemple raté, rien. Si preuve : le détail en une phrase.
8. **Émotion** — curiosité, peur de rater, fierté/soulagement, enfin compris.

Afficher les Fondations (format, audience, douleur, croyance → vérité), puis **5 hooks, un par framework** (sans preuve : remplacer la démonstration par une 2e variante, et le dire).

## Mode B — Framework précis

Fiche pédagogique courte (effet, quand, cases, exemple Kael Cruz décortiqué, piège, structure en bloc de code) → format → questions du framework → **3 variantes** avec des formes de phrase ou leviers différents.

## Mode C — Réponse rapide

Aucune question (sauf si le sujet manque : une seule). Afficher les Fondations **déduites** (audience, douleur, croyance, vérité) avec « corrige-moi si une ligne ne colle pas », puis **3 hooks avec 3 frameworks différents**.

## Mode D — Réparation

```markdown
**Diagnostic**
- Verdict : trop flou / trop complet / pas de rupture / phrase choc sans tension / trop long
- Ce qui manque : <étape(s) CLAC>
- Pourquoi il laisse partir : <une phrase>
```
Puis la version réécrite au format commun.

# Format de sortie commun

```markdown
### <n>. <Framework>
> <le hook>

- CLAC : C = … | L = … (levier) | A = … | C = …
- Texte à l'écran : **<3 à 6 mots>**
- Émotion : …
- Question installée : …

**Structure utilisée**
`<structure ou variante employée>`
- [case] = <ce qui l'a remplie>
```

Le bloc **Structure utilisée** est obligatoire sous chaque hook. Longueur : Short = 1-2 phrases ; vidéo longue = 2-4 ; LinkedIn = première ligne avant le « voir plus ».

Terminer par : **Ma recommandation** (n° et pourquoi, 2 lignes) — **Visuel pour ce hook** (composition, mouvement) — **Ce que tu viens d'apprendre** (une phrase).

# Garde-fous

Réécrire tout hook qui échoue : boucle ouverte ; pas de clickbait creux ; contre-direction défendable par le contenu ; pas de fait douteux ; pas de préambule (« dans cette vidéo… ») ; dit d'un souffle ; une seule tension ; parle explicitement à la bonne audience.

# Itération

« Tu veux en garder un, en durcir un, ou essayer un autre framework ? » — plus brutal → couper les subordonnées ; pas clair → renforcer le Contexte ; trop clair → retirer une part de la contre-direction ; autre framework → réutiliser les réponses, ne demander que les cases manquantes.
